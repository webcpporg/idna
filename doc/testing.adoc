[#idna-testing]
== Testing

[#idna-testing-library]
=== How idna is tested

idna's tests are lightweight_test programs, one per subject, under `test/`,
each declared in `test/Jamfile` with webcpp's `webcpp.run`, and run on every
target the Jamfile declares:

[cols="1,3",options="header"]
|===
| Test | What it checks

| `errors`
| The values of `idna::error`, which are fixed, their messages, the
  category's name and identity, and the message cut to a caller's buffer.

| `options`
| The strict profile's defaults, the designated initializers of the
  aggregate, the DNS lengths and the version of Unicode.

| `utf8`
| Strict UTF-8: the boundaries of every row of RFC 3629's table of
  well-formed sequences, decoded and encoded back, every kind of ill-formed
  one, and the end of the text.

| `punycode`
| RFC 3492 section 7.1's samples, (A) to (S), both ways, and inputs that
  tell apart what the samples leave alike in the bias; digits in either case
  and the mixed-case annotation kept; a leading delimiter, a bad digit, a
  number cut short, a value out of Unicode or a surrogate; each overflow of
  RFC 3492 section 6.4, in the decoder and the encoder; `output_too_small` at
  every length below the result's; the pmr forms.

| `allocation`
| The global `operator new`, replaced for this program alone: no call in a
  span form or a validator, and in a pmr form only those of its memory
  resource.

| `properties`
| One value of every generated table, through its lookup.

| `vectors`
| The generated vectors: every line of both files, the blank fields of
  IdnaTestV2.txt resolved, its lone surrogate kept ill-formed, the lines of
  the strict pass.

| `known_failures`
| The verdict a conformance test gives a line of IdnaTestV2.txt, held
  against `test/known_failures.json`: built twice more with
  `webcpp.run-fail`, it must fail on a listed line that passes and on an
  unlisted line that fails.

| `nfc`
| NFC within a label's storage against every line of
  NormalizationTest.txt, its quick check and its slow path, Hangul, and the
  storage, inline and growing: its edge after decomposition, at the
  capacity and one past it, canonical ordering against a stable sort, and a
  run of 10,000 non-starters normalized in less than 20 times the time of a
  text as long without one, which an insertion sort exceeds by far.

| `context`, `bidi`
| Each rule of RFC 5892 appendix A and of RFC 5893 section 2, satisfied and
  broken, the joining scripts a hand-written list misses among them, and
  A.7 to A.9 over labels of thousands of code points in less than 100 times
  the time of a label as long without a CONTEXTO code point.

| `process`
| The label driver in both forms on what ends a label early: an A-label that
  decodes to nothing, a label beyond the storage after an earlier error,
  gathered or in the NFC check's copy, and the empty labels, the root label
  among them, an undecodable label kept, and the ASCII form as given; and
  that it throws only what a memory resource throws. Like
  every test, built with the standard library's own checks on, so that a
  read past an empty label traps.

| `validity`
| `check_label` and `check_domain`: every rule with its error, and of two
  broken rules the earlier; the strings of the JSON Schema suite's
  `idn-hostname` that UTS 46 alone accepts, as U-labels and as A-labels;
  A-labels in either case, not ASCII, decoding to ASCII, and labels that
  only look like one; the lengths at 63 and 64, 253 and 254; the inline
  storage's limit; the first error of a name with several; a name of 65,536
  labels checked in less than 20 times the time of a name as long of labels
  of 255 letters; and the rows of IdnaTestV2.txt in both passes, as given:
  each output the file records without an error is valid, its A-labels in
  uppercase too, and a source already in its processed form, or in its ASCII
  form, has the verdict the file gives it.

| `uts46`
| Every line of IdnaTestV2.txt, toUnicode, toAsciiN and toAsciiT, in the
  span and the pmr forms, under UTS 46 alone as the file assumes, then the
  strict profile over the lines whose toUnicode field holds no NV8, XV8 or
  CONTEXTO code point; and the orders of the errors, the same in both forms
  under the DNS lengths. Then the pmr forms' bound on a label's Punycode,
  256 code points: a label of 16,384 distinct ideographs, and an A-label of
  131,072, refused in less than 10 times the time of a label as long of one
  ideograph, which the unbounded encoder exceeds by far; and names of labels
  at the bound converted in less than 10 times the time of their linear
  twins.
|===

Beside them, `test/Jamfile` compiles each of the {n-headers} headers alone,
and `config.hpp` twice, as the build asks and with
`WEBCPP_IDNA_NO_EXCEPTIONS` defined by the developer. `example/Jamfile`
builds every program this page shows, runs it, and compares what it printed
with the `.expected` beside it. The own lane `tables`,
`b2 -a libs/idna/test//tables`, checks the generated files against the
generator (<<idna-unicode-generator>>).

[#idna-testing-targets]
=== Targets and exceptions

`test/Jamfile` declares `webcpp.targets native wasip2 wasip3 emscripten`:
natively with any toolset, for wasm32-wasip2 and wasm32-wasip3 with the
toolsets `clang-wasip2` and `clang-wasip3` run by wasmtime, and with
Emscripten run by Node.

`<webcpp/idna/config.hpp>`, which every public header includes first,
defines `WEBCPP_IDNA_NO_EXCEPTIONS` when the build has no exceptions, and a
program may define it itself, as Boost.Asio's `BOOST_ASIO_NO_EXCEPTIONS`.
idna raises no exception of its own, so the macro changes nothing in it: it
exists so that a program can set it for every webcpp library alike. The
lint compiles every header and test a second time without exceptions.
