[#idna-unicode]
== Unicode and the tables

idna's tables follow Unicode {unicode-version},
`idna::unicode_version`, and UTS{nbsp}46 revision {uts46-revision} for it. They
are generated from Unicode's data files into
`<webcpp/idna/detail/tables.hpp>` as `constexpr` arrays of constant data,
never written: no table is built at run time, none is compressed, nothing is
allocated and nothing is shared mutable state, so any number of threads may
call idna at once. Each property is a sorted list of runs, looked up by
binary search.

[cols="2,3,3",options="header"]
|===
| Table | From | Used by

| UTS{nbsp}46 status, NV8 and XV8 mark, mapping
| `idna/IdnaMappingTable.txt`
| the mapping, V7, IDNA2008's property

| Bidi_Class
| `ucd/extracted/DerivedBidiClass.txt`
| RFC{nbsp}5893

| Joining_Type
| `ucd/extracted/DerivedJoiningType.txt`
| RFC{nbsp}5892 A.1

| Canonical_Combining_Class
| `ucd/extracted/DerivedCombiningClass.txt`
| NFC, and the virama of A.1 and A.2

| General_Category Mark
| `ucd/UnicodeData.txt`
| V6

| Script: Greek, Hebrew, Hiragana, Katakana, Han
| `ucd/Scripts.txt`
| RFC{nbsp}5892 A.4 to A.7

| canonical decompositions, primary composites, NFC_Quick_Check
| `ucd/UnicodeData.txt`, `ucd/DerivedNormalizationProps.txt`
| NFC
|===

Hangul syllables are decomposed and composed by the arithmetic of Unicode
section 3.12, and take no table.

[#idna-unicode-generator]
=== The generator

`tools/generate_tables.py`, in idna's repository, writes the tables, and
the vectors of the conformance tests, `IdnaTestV2.txt` and
`NormalizationTest.txt` as {cpp} data under `test/generated/`
(<<idna-testing>>). Its inputs are pinned in `tools/unicode.json`, each by
its URL under `\https://www.unicode.org/Public/{unicode-version}/` and its
SHA-256, with IANA's IDNA2008 tables, `idna-tables-12.0.0`, read only by
its checks. A file its cache lacks is downloaded, every file is hashed, and
a digest that differs stops it, naming the file and both digests, before it
writes anything.

Before it writes, it checks what idna assumes of the data, and stops naming
the assumption that fails: every status of the mapping table is one of the
five it knows; IANA's IDNA2008 property of every code point IANA assigns one
agrees with the derivation from UTS{nbsp}46's table, U+002E FULL STOP aside, which
IANA disallows and UTS{nbsp}46 keeps as the separator no label holds; the
CONTEXTJ and CONTEXTO code points are those of RFC{nbsp}5892 appendix A; no full
canonical decomposition is longer than 4 code points; no Hangul syllable has
a decomposition in `UnicodeData.txt`, since idna computes those; and every
property value a file holds is one it knows, either one the tables keep or
one it reads as other. It reads the test files as strictly: every line of
`IdnaTestV2.txt` has its seven fields, its status codes take the forms the
file's header names, and its one escape is `\uXXXX`; every line of
`NormalizationTest.txt` has its five columns of code points; and each entry
of `test/known_failures.json` names a line of `IdnaTestV2.txt` by its number
and its source, once, with a reason, for the pinned version of Unicode. Two
runs write the same bytes. Its cache is `bin/unicode/{unicode-version}/` of
the superproject, which it fills from
unicode.org and iana.org when a file is missing. The data are Unicode's,
under the Unicode License v3, whose notice is in
<<idna-unicode-data,the appendix "Unicode data">>.

The own lane `tables` runs the generator again, into the build directory, and
compares each of its outputs with the committed file, byte for byte, naming
each that differs; `update-generated` writes them in place, and is the one
writer of the generated files. The ordinary lanes never run the generator,
which may need the network; the CI runs the lane on its own.

[source,bash]
----
b2 -a libs/idna/test//tables
b2 libs/idna/test//update-generated
----

[#idna-unicode-compile]
=== What the tables cost

Only `<webcpp/idna/detail/properties.hpp>` includes the tables, and of the
public headers only `uts46.hpp` and `validity.hpp` reach it, with
`<webcpp/idna.hpp>`, which includes them: `punycode.hpp`, `errors.hpp` and
`options.hpp` cost nothing of them. The tables hold 147,324 bytes of data,
and a program links only those it reads. A translation unit that includes
`<webcpp/idna.hpp>` and calls `to_ascii`, compiled at `-O2`, takes about
0.7 s of processor time and makes an object of 188 KB natively with Apple
Clang 21, and about 0.8 s and 197 KB for wasm32-wasip2 with wasi-sdk 34,
against 0.14 s and 0.07 s, and under 1 KB, for the same program without
idna. Each time is the least of fifteen compilations, user and system time,
on an Apple M5 Max shared with other work.

[#idna-unicode-moving]
=== Moving to another version of Unicode

A move is one change of its own, which updates every place that holds the
version, in this order:

. `tools/unicode.json`: its `version`, and the `url` and the `sha256` of
  each of Unicode's files. IANA's `idna-tables-12.0.0` stays as it is.
  `test/known_failures.json`: its `unicode`, and no entry, since each names
  a line of the old `IdnaTestV2.txt`.
. `tools/generate_tables.py`, run from the superproject's root by
  `b2 libs/idna/test//update-generated`, which downloads the new files. A
  property value the new version adds, most often a script, stops it by
  name. The value then joins the generator's list of the values it reads as
  other, `SCRIPT_OTHERS`, `BIDI_OTHERS`, `JOINING_OTHERS` or
  `OTHER_CATEGORIES`, once it is known not to matter to IDNA, or the values
  the tables keep, `SCRIPTS`, `BIDI_CLASSES` or `JOINING_TYPES`, with the
  code that reads them, when it does; the comment above those lists names
  the version they were read from. Any other check that fails is an
  assumption of idna's that no longer holds, and is settled before the move
  goes on. Once every check passes, `update-generated` writes
  `include/webcpp/idna/detail/tables.hpp` and the vectors again.
. `include/webcpp/idna/options.hpp`: `unicode_version`, which
  `detail/properties.hpp` refuses to compile while it differs from the
  tables'; the version that `test/options_test.cpp` and
  `test/properties_test.cpp` pin; and the counts and line numbers of the
  test files that `test/vectors_test.cpp` pins.
. `doc/idna.adoc`: the attributes `:unicode-version:` and
  `:uts46-revision:`, which every mention of the version and of UTS{nbsp}46's
  revision on this page reads.
. The text that names the version: the `description` of
  `meta/libraries.json`, the first paragraph of `README.md`, and the section
  "Unicode and the tables" of `AGENTS.md`.
. Every lane, the own lane `tables` among them, and the known failures of
  `test/known_failures.json` brought up to date, each with its reason, and
  `update-generated` run again, which writes each reason into its row.
. The changelog, in a line that names the new version.
